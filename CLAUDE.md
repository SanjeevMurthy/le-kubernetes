# le-kubernetes

Certification preparation repository covering the CNCF Kubernetes certifications (Kubestronaut) plus LFCS (Golden Kubestronaut).

## Repository Structure

```
le-kubernetes/
├── cka/              # CKA - Certified Kubernetes Administrator (passed)
├── ckad/             # CKAD - Certified Kubernetes Application Developer (passed)
├── cks/              # CKS - Certified Kubernetes Security Specialist (in progress, exam 12 Dec 2026)
├── lfcs/             # LFCS - Linux Foundation Certified System Administrator (exam 6 Feb 2027)
├── kcna/             # KCNA - Kubernetes and Cloud Native Associate (planned)
├── kcsa/             # KCSA - Kubernetes and Cloud Native Security Associate (planned)
├── shared/           # Common manifests and cluster setup scripts
├── scripts/          # Repo-wide verification tooling
├── docs/research/    # Evidence behind the study material
├── docs/superpowers/ # Design spec and implementation plans
└── roadmap.md        # Both exams on one page
```

## Conventions

- Each certification has its own top-level directory (lowercase).
- Directory and file names use lowercase with hyphens, no spaces.
- YAML manifests use descriptive filenames matching the K8s resource they define.
- Do not commit secrets, keys, or credentials (enforced via `.gitignore`).
- PDFs and binary resources go under `<cert>/resources/`.
- Practice CLI runtime state (`.timer`, `.progress`, mock results) lives outside the repo, in `~/.cks-practice` or `/var/lib/lfcs`.

## Verification: run this before every commit

```bash
bash scripts/check-docs.sh          # bash -n, shellcheck, links and anchors, TOCs, mermaid
```

It must print `check-docs: ALL OK`. The individual tools are also usable directly:

| Script | Purpose |
|---|---|
| `scripts/check-links.py` | relative links, images, heading anchors and HTML `<a id>` anchors |
| `scripts/generate_toc.py` | `--inject` to add a TOC, `--check` to verify one is current |
| `scripts/check-mermaid.sh` | lints every mermaid block and renders it with mermaid-cli when `npx` exists |
| `scripts/check-question-refs.py` | every `Q<n>` named in notes, checklists and mock sets exists on disk |
| `scripts/check-persistence.py` | every LFCS verifier checks a change survives a reboot, or is listed exempt with a reason |
| `scripts/build-lab-table.py` | regenerates each kit's "which questions run where" table from the question metas |
| `scripts/test-libs.sh` | unit tests for the shared library helpers |
| `scripts/check-docs.sh` | runs all of the above plus shell syntax checks and shellcheck |

Anything generated is rebuilt by one command:

```bash
bash scripts/regenerate.sh          # registries, guides, mock papers, lab tables, markers, TOCs
```

Run it after adding, renaming or retagging any question, then run the gate.

`MERMAID_RENDER=0` skips rendering when the Chromium download is unwanted.

## Documentation conventions

- Every markdown file with H2 headings carries a `<!-- toc -->` / `<!-- toc stop -->` block, generated by `scripts/generate_toc.py --inject`. Never hand-write one.
- Study notes are **exam-task recipes**, not reference material. Each recipe is: `**Goal.**`, `**Frequency.**`, `**Commands.**` with a fenced block, `**Verify.**` with a fenced block, `**Gotchas.**` bullets, `**Docs.**`.
- The `**Docs.**` line names the documentation actually allowed in that exam, or says explicitly that none is and the flags must be memorised.
- At most one mermaid diagram per note, and only when it shows a flow.
- Every frequency claim ("12 sources") is a count of independent candidate reports traceable to `docs/research/`.
- Prose style: plain sentences, no em-dashes. Commands live in fenced blocks, not inline in paragraphs.

## Practice CLI contract

`cka/practice-cli/{v1,v2}` and `ckad/practice-cli` are the original harnesses and keep a single monolithic guide file. `cks/practice-cli` is the current design and `lfcs/practice-cli` follows it.

Each question is a self-contained folder:

```
questions/qNN-<slug>/
├── meta          # bash-sourceable: id, title, domain, domain_short, difficulty,
│                 # needs, weight, minutes, sources, host
├── question.md   # shown by [Q]; exam wording, exact names and paths
├── solution.md   # shown by [H]; steps, why, verification, docs
├── setup.sh      # creates the real starting state; prints the scenario facts
├── verify.sh     # PASS/FAIL checks that test effect; exits non-zero on failure
└── cleanup.sh    # deletes what setup made and restores every backup
```

Generated files, never edited by hand:

```bash
bash tools/build-registry.sh   # questions/*/meta  -> lib/questions.sh
bash tools/build-guide.sh      # questions/*/      -> <cert>-exam-qa-guide.md
bash tools/build-mock.sh N     # mock-exams/mock-N.set -> mock-N.md
```

Each generator refuses to overwrite its output when the inputs look wrong.

### Needs tags

`meta`'s `needs` field lists what a question requires; `./cks --env` matches them against the current host and reports which questions can run.

`kubectl`, `linux`, `cni-netpol`, `cni-cilium`, `ingress`, `admission:kyverno`, `admission:gatekeeper`, `istio`, `node-root`, `tool:<name>`. The LFCS CLI adds `disk`, `netns`, `host2`, `nic2`, `rocky`, `ubuntu`, `virt`.

### Rules for question scripts

- Verifiers test **effect**, not file text: `kubectl auth can-i`, a `curl` through the Ingress, `aa-status`, audit-log growth, the `k8s:enc:` prefix in etcd.
- Never grep compact JSON. `kubectl -o json` is pretty-printed, so `'"app":"backend"'` never matches. Use `-o jsonpath`.
- There is no `jq` in either exam environment. Use `-o jsonpath`, `-o go-template` or `yq`.
- Setups back up every file they modify (`backup_file`); cleanups restore them (`restore_file`).
- Never restore a whole-file snapshot of `/etc/fstab`. Several storage questions can be set up at once, so a snapshot does not know about the other questions' lines. Cleanups call `fstab_drop_target` to remove only their own. A wrong `/etc/fstab` stops the next boot.
- A cleanup deletes an account, group or directory only when its setup recorded creating it. A host with a real account of that name must keep it.
- Every LFCS verifier checks persistence separately from live effect, because the exam scores an unpersisted change as zero. `scripts/check-persistence.py` enforces this.
- Setup output is shown to the candidate, so print the scenario facts.
- Menu and library code stays bash 3.2 compatible so it can be smoke-tested on macOS. Question scripts run on Linux and may use bash 4.

### Safety guards

The CKS CLI refuses any kubectl context matching `aks`, `eks`, `gke` or `prod`, and anything not on its allow-list, unless `CKS_ALLOW_CONTEXT=1`. The LFCS CLI requires root and refuses to run on a host without `/etc/lfcs-lab`. These are not theoretical: the default context on the owner's machine is a work AKS cluster.

## Working on this repo

- Branch per certification (`cks`, `lfcs`), with a pull request at the end of each build phase.
- Run `bash scripts/check-docs.sh` before every commit.
- Question scripts that touch nodes cannot be tested on macOS. They are syntax-checked locally and smoke-tested by the owner on Killercoda or in the LFCS VM before a phase is called done.
- When a study plan's dates change, update `roadmap.md` too.
