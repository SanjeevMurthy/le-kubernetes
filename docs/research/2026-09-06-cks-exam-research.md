### 1.2 Every sub-topic bullet, verbatim (CKS_Curriculum v1.34.pdf) — OFFICIAL

| Domain (weight) | Bullets (verbatim) |
|---|---|
| **15% – Cluster Setup** | • Use Network security policies to restrict cluster level access<br>• Use CIS benchmark to review the security configuration of Kubernetes components (etcd, kubelet, kubedns, kubeapi)<br>• Properly set up Ingress objects with TLS<br>• Protect node metadata and endpoints<br>• Verify platform binaries before deploying |
| **15% – Cluster Hardening** | • Use Role Based Access Controls to minimize exposure<br>• Exercise caution in using service accounts e.g. disable defaults, minimize permissions on newly created ones<br>• Restrict access to Kubernetes API<br>• Upgrade Kubernetes to avoid vulnerabilities |
| **10% – System Hardening** | • Minimize host OS footprint (reduce attack surface)<br>• Using least-privilege identity and access management<br>• Minimize external access to the network<br>• Appropriately use kernel hardening tools such as AppArmor, seccomp |
| **20% – Minimize Microservice Vulnerabilities** | • Use appropriate pod security standards<br>• Manage kubernetes secrets<br>• Understand and implement isolation techniques (multi-tenancy, sandboxed containers, etc.)<br>• Implement Pod-to-Pod encryption (Cilium, Istio) |
| **20% – Supply Chain Security** | • Minimize base image footprint<br>• Understand your supply chain (e.g. SBOM, CI/CD, artifact repositories)<br>• Secure your supply chain (permitted registries, sign and validate artifacts, etc.)<br>• Perform static analysis of user workloads and container images (e.g. Kubesec, KubeLinter) |
| **20% – Monitoring, Logging and Runtime Security** | • Perform behavioral analytics to detect malicious activities<br>• Detect threats within physical infrastructure, apps, networks, data, users and workloads<br>• Investigate and identify phases of attack and bad actors within the environment<br>• Ensure immutability of containers at runtime<br>• Use Kubernetes audit logs to monitor access |

Source: https://raw.githubusercontent.com/cncf/curriculum/master/CKS_Curriculum%20v1.34.pdf

From "Resources Allowed: All LF Certification Programs", CKS section (https://docs.linuxfoundation.org/tc-docs/certification/certification-resources-allowed ; verbatim text confirmed in https://docs.linuxfoundation.org/tc-docs/llms-full.txt):

> - **Cilium** Documentation https://docs.cilium.io/en/stable
> - **Istio** Documentation https://istio.io/latest/docs/

> - This includes all available language translations (e.g. https://kubernetes.io/zh/docs/) …
> - Review the Exam content instructions that are presented in the command line terminal
> - Review Documents installed by the distribution (i.e. /usr/share and its subdirectories)
> - Use packages that are part of the distribution (may also be installed by Candidate if not available by default)

**Not on the current list:** AppArmor docs (gitlab.com/apparmor), Trivy docs (aquasecurity.github.io/trivy), kube-bench docs, github.com/kubernetes. Older community lists (e.g. https://github.com/walidshaari/Certified-Kubernetes-Security-Specialist , CANDIDATE-REPORTED, 2021–2023) still show Trivy and AppArmor as allowed; that is out of date. INFERRED: since the exam expects Trivy/kube-bench/AppArmor tasks without their docs, `trivy --help`, `kube-bench --help`, `man apparmor_parser`, and `/usr/share/doc` are the only in-exam references for those tools, so the kit must drill their CLI flags from memory. Note also that Ingress NGINX was retired by the Kubernetes project in March 2026 ("no further releases, no bugfixes, and no updates to resolve any security vulnerabilities", existing deployments keep working) — OFFICIAL — https://www.kubernetes.dev/blog/2025/11/12/ingress-nginx-retirement/ ; the CKS allowed list still references its user guide, so INFERRED the exam's TLS-Ingress task still uses ingress-nginx.

### 2.1 Synthesis (INFERRED from the table above)

**Most recommended resources (by count of write-ups naming them):** killer.sh simulator (named in 20 of the 28 entries), KodeKloud CKS course + mocks (15), Killercoda Killer-Shell CKS scenarios (11), Kim Wüstkamp's course (Udemy or the free 11-hour YouTube version) (7), official kubernetes.io/falco.org/cilium docs (most). Nobody in 2025–2026 recommends LFS260; O'Reilly/Muschko is cited once (cuffaro's era used Liz Rice instead).

**Time-management consensus:** scan every task first, then do high-weight and "known" tasks (Walter Lee, Giorgi, Rajat Umrao, Kienlt); cap any task at 6–10 minutes before flagging (Kienlt, Giorgi); keep 15–20 minutes to verify (Arslan, Giorgi); expect 2–3 sub-tasks per question (Trung Tran); "impossible … to answer all questions in 2 hours" for most (hemjal1) — INFERRED: passing at 67% with 16 tasks means roughly 11 solid tasks, so skipping 3–4 is survivable.

**Common causes of failure (each cited by ≥1 first-hand fail report):** (1) running out of time / spending the first hour on 3 questions (Arslan, suzuki0430, gentx2, hemjal1, kubegeek); (2) weak Linux administration (users/groups, systemctl, grep) (suzuki0430); (3) breaking the kube-apiserver while wiring ImagePolicyWebhook or editing the static pod (Valiev; KodeKloud: "If you fail to recover a crashed API server it is very likely you'll lose all marks for the question", https://github.com/kodekloudhub/cka-debugging-api-server ); (4) underestimating Falco and Cilium depth (Parasxidis, Arslan, Toon); (5) skipping a topic in prep (Arnav skipped Falco; kaizendae was surprised by seccomp); (6) practising only KodeKloud (hemjal1) or only killer.sh (Arnav's overconfidence); (7) exam-environment unfamiliarity — Firefox latency, copy/paste keys, no bookmarks (Arnav, Rajat Umrao, Arslan who bought Killercoda PRO for the exam desktop).

**Retake pattern:** of the 28 entries, 8 report a first-attempt fail (Valiev 55, suzuki0430 44, Toon 57/66, Arslan, Mauricio 44/64, Arnav 49, kubegeek, Parasxidis) and every one of them passed on a later attempt within days to weeks, typically with a large jump (55→90, 44→79, 49→74). INFERRED: the free retake is part of the plan; schedule the first attempt with ≥6 weeks of eligibility left.

## 5. Exam-day technique

### 5.1 Environment setup at the start (first 2–3 minutes)

- Aliases: `k` with completion is pre-configured on every task host (OFFICIAL, https://docs.linuxfoundation.org/tc-docs/certification/important-instructions-cks ). Because each task is done on a different SSH host, per-shell aliases do not persist; two 2025 candidates advise not bothering with custom aliases at all (kaizendae https://www.kaizendae.com/blog/CKS ; KodeKloud forum https://kodekloud.com/community/t/cks-exam-experience/463973 ). If you do, keep it to one line typed on the host you are on: `export do="--dry-run=client -o yaml"` (fireflycons https://github.com/fireflycons/tips-for-CKA-CKAD-CKS ; Giorgi https://www.linkedin.com/pulse/how-ace-cks-20-certified-kubernetes-security-exam-giorgi-keratishvili-gw2sf ). INFERRED: for the practice CLI, train without aliases beyond `k`.
- Vim: `set nu sw=2 et ts=2 ai` (fireflycons; Killercoda has a dedicated "Vim Setup" scenario, https://killercoda.com/killer-shell-cks ); `:set paste` before pasting YAML (fireflycons); INSERT key is disabled — press `i` (OFFICIAL). Visual-line `Shift+V`, `>`/`<` to indent blocks (fireflycons).
- Copy/paste: terminal `Ctrl+Shift+C/V`, Firefox `Ctrl+C/V`, right-click works everywhere, `Ctrl+Alt+W` not `Ctrl+W` (OFFICIAL, same page). Disable the terminal's "unsafe paste" dialog (fireflycons; Wüstkamp https://itnext.io/cks-cka-ckad-changed-terminal-to-remote-desktop-157a26c1d5e ).
- Two terminals: keep `vi` open in one and run `kubectl apply` / `watch kubectl get pod -n kube-system` in the other (fireflycons; Lakhera https://devopslearning.medium.com/my-road-to-certified-kubernetes-security-specialist-cks-d26a8e9b50bc ). VSCodium with its integrated terminal is also available (OFFICIAL, https://docs.linuxfoundation.org/tc-docs/llms-full.txt ).
- Font: use the PSI toolbar +/– zoom; 1080p and a 15"+ screen recommended (OFFICIAL); external monitor advice (Mauricio).

### 5.2 Documentation strategy (no bookmarks)

- Personal bookmarks are not possible; the remote Firefox has "Documentation Quick Links" and each task has a "Quick Reference" box with task-specific links (CANDIDATE-REPORTED https://kodekloud.com/blog/ckad-cka-cks-new-psi-exam-environment/ ; OFFICIAL https://docs.linuxfoundation.org/tc-docs/certification/certification-resources-allowed ). Use the kubernetes.io search box (allowed) but never external search results (OFFICIAL).
- Memorise the page *titles* you will search for: "Auditing", "Encrypting Confidential Data at Rest", "Restrict a Container's Access to Resources with AppArmor", "Restrict a Container's Syscalls with seccomp", "Enforce Pod Security Standards with Namespace Labels", "Network Policies", "Using RBAC Authorization", "ImagePolicyWebhook" (Admission Controllers reference), "Runtime Class", "Certificate Signing Requests", "Upgrading kubeadm clusters"; plus falco.org "Supported Fields" and "Rules" pages (Tuladhar https://dev.to/ptuladhar3/falco-must-know-for-cks-exam-7en ), docs.cilium.io "Network Policy" and "Transparent Encryption". INFERRED from the allowed list and the task table.
- `kubectl explain pod.spec.securityContext` beats the docs for field names (fireflycons; Kienlt). Resize Firefox so `Ctrl+F` works (OFFICIAL; Arnav).

### 5.3 Question ordering and time per task

- Read the ReadMe, then skim all tasks and note weight and cluster/host (Giorgi; Rajat Umrao; Walter Lee "Parse all questions at exam start"). Do high-weight and confident tasks first; leave cluster upgrade, ImagePolicyWebhook and audit-policy tasks (reported as the most time-consuming: Valiev) for after the quick wins. Budget 6–8 min average (sailor.sh https://sailor.sh/blog/cks-exam-guide-2026/ ), hard cap 6–10 min before flagging (Kienlt; Giorgi). Keep 15–20 min to verify (Arslan; Giorgi). Partial credit exists ("correct partial tasks count", cuffaro), so attempt every task at least partially.
- Always run the `kubectl config use-context …` line given in each task and confirm the host (jayendrapatil https://jayendrapatil.com/certified-kubernetes-security-specialist-cks-learning-path/ ; Walter Lee "Set context FIRST"; Rajat Umrao "Revalidate your context"). Return to `base` after every task (OFFICIAL).
- Use `--force --grace-period=0` when recreating pods (Walter Lee); `k replace --force -f` (Ron Amosa).

### 5.4 Common mistakes and recoveries

| Mistake | Reported by | Recovery / prevention |
|---|---|---|
| Editing the static pod manifest and killing the apiserver (bad flag, missing volume, YAML indentation, wrong kubeconfig `server:` for ImagePolicyWebhook) | Valiev; suzuki0430; Walter Lee; KodeKloud ("very likely you'll lose all marks for the question", https://github.com/kodekloudhub/cka-debugging-api-server ) | `cp /etc/kubernetes/manifests/kube-apiserver.yaml /root/kube-apiserver.yaml.bak` first (Giorgi, Valiev, Trung Tran, Lakhera). If `kubectl` hangs: `systemctl restart kubelet`; `journalctl -fu kubelet | grep apiserver` for ~60 s to catch "Could not process manifest file" (YAML) errors; `crictl ps -a | grep apiserver` and `crictl logs <id>`; for immediate crashes `ls -ld /var/log/pods/*apiserver*` → newest dir → `kube-apiserver/*.log` (KodeKloud community FAQ https://github.com/kodekloudhub/community-faq/blob/main/docs/diagnose-crashed-apiserver.md ). The kubelet rescans `/etc/kubernetes/manifests` every 20 s, so wait rather than re-edit repeatedly (sailor.sh CKA guide via search summary, https://sailor.sh/blog/cka-cluster-application-monitoring-metrics-server-kubectl-top-logs/ ). Killercoda "Apiserver Crash"/"Apiserver Misconfigured" scenarios rehearse exactly this. |
| Wrong context/namespace/node | Walter Lee; Rajat Umrao; Prasad | Copy-paste the context line; `k config current-context`; check the task infobox host; file-modification tasks happen on the control plane node, AppArmor/kubelet tasks on the named worker |
| Not restarting kubelet after kubelet-config or AppArmor changes | Walter Lee; Ron Amosa | `systemctl restart kubelet && systemctl status kubelet`; `aa-status | grep <profile>` |
| Deleting the wrong resource | Rajat Umrao ("no way to reset anything") | `k get … -o yaml > backup.yaml` before delete; read the task twice |
| Spending the first hour on 2–3 tasks | Arslan; hemjal1; gentx2 | Flag at 8–10 min; the Review Screen lists flagged items (OFFICIAL) |
| Writing answers to the wrong place (file vs deletion) | Trivy-task note in KodeKloud forum/search summary; jayendrapatil ("Read carefully the Information … with the i mark") | Re-read the deliverable line ("write … to /opt/course/N/…") before moving on |
| Verifying too little | suzuki0430; Arnav | Every hardening task has a test: `k auth can-i`, `curl -k https://…`, `k run test --rm -it --image busybox`, `etcdctl get`, `dmesg` in gVisor pod, `journalctl -u falco` / `cat /var/log/falco.log` |
| Slow remote desktop at off-peak hours | Rajat Umrao (2 AM) | Book a daytime slot; minimise Firefox tab use; work in the terminal |
| Not arriving 30 min early / room-scan delays | Giorgi; fireflycons | Use the full 30-minute early check-in |

### 5.5 Reusable snippets candidates recommend memorising (CANDIDATE-REPORTED unless noted)

- `apparmor_parser -q /etc/apparmor.d/<file>` ; `aa-status` (Prasad; Ron Amosa).
- Seccomp: profiles in `/var/lib/kubelet/seccomp/profiles/`; pod `securityContext.seccompProfile: {type: Localhost, localhostProfile: profiles/audit.json}` (Lakhera; Ron Amosa; Kubernetes docs https://kubernetes.io/docs/tutorials/security/seccomp/ OFFICIAL).
- Falco: `/etc/falco/falco_rules.local.yaml`, `systemctl restart falco`, `falco --list`, `journalctl -u falco` (Prasad; Namrata D; Tuladhar).
- Audit flags: `--audit-policy-file`, `--audit-log-path`, `--audit-log-maxage`, `--audit-log-maxbackup`, `--audit-log-maxsize` + two hostPath volumes (Rafael Medeiros; Kubernetes docs https://kubernetes.io/docs/tasks/debug/debug-cluster/audit/ OFFICIAL).
- etcd: `ETCDCTL_API=3 etcdctl --cacert … --cert … --key … get /registry/secrets/<ns>/<name>` (theJaxon; KodeKloud notes https://notes.kodekloud.com/docs/Certified-Kubernetes-Security-Specialist-CKS/Minimize-Microservice-Vulnerabilities/Demo-Encrypting-Secret-Data-at-Rest/page ).
- Re-encrypt: `kubectl get secrets -A -o json | kubectl replace -f -` (Kubernetes docs https://kubernetes.io/docs/tasks/administer-cluster/encrypt-data/ OFFICIAL).
- Binaries: `sha512sum <bin>`; `echo "<hash> <bin>" | sha512sum --check` (Muqees).
- Trivy: `trivy image --severity HIGH,CRITICAL <image>` (jayendrapatil; KodeKloud notes).
- Cilium: `kubectl -n kube-system exec ds/cilium -- cilium encrypt status` (Tuladhar).

## 7. Implications for the preparation kit (INFERRED)

1. **Question bank weighting.** Build ~60 tasks: Falco (6), audit (5), ImagePolicyWebhook (4), kube-bench/CIS incl. kubelet and etcd TLS (6), AppArmor (4), seccomp (3), NetworkPolicy incl. DNS/metadata/Cilium (7), RBAC/SA (5), gVisor (3), apiserver flags & crash recovery (5), secrets/etcd encryption (4), Trivy/static analysis/SBOM/kubesec (6), Ingress TLS (2), PSA (3), immutability (2), upgrade (2), CSR (2), Linux hardening (3), Istio (1).
2. **Every task = setup.sh / verify.sh / cleanup.sh on a kubeadm cluster**, mirroring the exam's "designated host + `sudo -i`" model; use `/opt/course/<n>/` paths and killer.sh-style deliverables (files under `/opt/course`), since that is what candidates and all simulators use.
3. **Mandatory drills:** (a) break-and-recover kube-apiserver three ways; (b) Falco output-format task with `crictl` mapping; (c) ImagePolicyWebhook with a deliberately wrong kubeconfig; (d) kube-bench fix → kubelet restart; (e) etcd encrypt + re-encrypt + etcdctl proof; (f) 16-task timed mock in 120 min with weights.
4. **Study plan:** candidates who passed spent 2–6 weeks at 1–3 h/day (Aditya Joshi 2 weeks; kaizendae 40 days; suzuki0430 80 h/5 weeks; Arnav 5–6 weeks; cuffaro 6 weeks), using killer.sh session 1 two weeks out and session 2 two to three days out (KodeKloud FAQ). Voucher expires March 2027, so a first attempt by January 2027 leaves room for the free retake.
5. **Re-verify before booking:** the Kubernetes version line on https://docs.linuxfoundation.org/tc-docs/certification/faq-cka-ckad-cks and the allowed-docs list on https://docs.linuxfoundation.org/tc-docs/certification/certification-resources-allowed .
